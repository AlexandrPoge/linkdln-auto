# Gmail API: подключение без SMTP и пароля приложения

Поиск работает без почты. Для отправки и чтения уведомлений реализован Gmail API через HTTPS. Сам вход выполняется на стороне Google в обычном системном браузере (Chrome/Safari), не во встроенном браузере Codex. Пароль Google и пароль приложения нашему серверу не нужны.

## Один раз настроить свой OAuth-клиент

1. В [Google Cloud Console](https://console.cloud.google.com/) выбери или создай свой проект. Не требуется развёртывание нашего сервера в облаке. Если Google предлагает оплату/условия, внимательно проверь их сам — приложение не принимает их автоматически.
2. В API Library включи **Gmail API**.
3. В **Google Auth Platform** настрой Branding и Audience: External, статус Testing, добавь `incognitor29@gmail.com` в Test users. Используй собственные название приложения и контактную почту.
4. В Clients создай OAuth client типа **Desktop app**, скачай JSON. Не выбирай Web application, API key или Service account.
5. В нашей панели **Автопилот → Настроить OAuth-клиент** вставь содержимое JSON и сохрани его локально. Не отправляй JSON или его секрет в чат/Git.
6. Нажми **Войти с Google · системный браузер**. Если браузер не открылся автоматически, скопируй полученную ссылку в Chrome/Safari. Авторизационная сессия действует 10 минут; после перезапуска сервера начни заново.
7. Самостоятельно выбери свой аккаунт Gmail и проверь запрошенные разрешения. Не обходи неожиданные предупреждения безопасности. После согласия Google вернёт браузер на `http://127.0.0.1:8765/gmail-callback` (используется фактический порт сервера).
8. Проверь PDF резюме, включи необходимые этапы (уведомления, чтение Job Alerts, отправка откликов, автоутверждение) и нажми **Сохранить и запустить цикл**. После подключения все этапы почты выключены до этого явного действия.

Реальное подключение нельзя завершить без клиентского JSON и твоего согласия в Google. Кнопка отключена до настройки клиента; успешный интерфейс не означает успешную авторизацию. Подключение проверяется запросом профиля Gmail, без тестового письма.

## Разрешения и безопасность

Запрашиваются `gmail.readonly` и `gmail.send`: Google разрешает чтение всей почты, а не только Job Alerts; приложение ограничивает обработку уведомлениями LinkedIn/hh/rabota.by в INBOX. Не запрашиваются удаление, изменение меток, контакты или Drive. Gmail readonly относится к restricted scopes, send — sensitive scope: распространение приложения среди других пользователей может требовать проверки Google. Внешний OAuth-проект в Testing обычно выдаёт refresh token на 7 дней — для постоянного использования нужно учитывать статус проекта и требования Google, а не обещать бессрочный доступ.

PKCE S256, случайный одноразовый `state`, ограниченный срок сессии и фиксированные HTTPS-endpoints защищают обмен кодом. Callback проверяет Host; локальные POST-формы — CSRF/Origin. OAuth-клиент, access/refresh tokens и история обработанных ID сохраняются атомарно с правами 0600 в Git-игнорируемых `data/gmail-client.json`, `data/gmail-token.json`, `data/gmail-alerts-seen.json`. Это не шифрование и не системная связка ключей: защищай компьютер и резервные копии. Токены/пароли не выводятся в панель или ошибки; произвольные серверные ответы не показываются.

Access token обновляется до истечения. API send никогда не повторяется автоматически, в том числе после 401/сетевого сбоя: потерянный ответ может означать, что письмо уже доставлено. Используется прежняя история доставок и лимит 1–10 попыток за 24 часа, по умолчанию 5. Смена SMTP на API не даёт повторно отправить тот же отклик.

**Отключить почту локально** очищает локальные токены и старый SMTP-пароль; поиск остаётся включён. Это не удаляет письма и не отзывает разрешение на стороне Google. Для полного отзыва используй [подключения аккаунта Google](https://myaccount.google.com/connections). Уже начатый цикл нельзя разрывать кнопкой: дождись его завершения. OAuth-клиент остаётся сохранённым для повторного входа.

## Если подключение не проходит

- `HTTP 403`: проверь включение Gmail API, Test users и разрешения.
- `HTTP 400/401`: возможны неверный тип клиента, истёкший/отозванный доступ; переподключи аккаунт. Серверное сообщение намеренно не раскрывается.
- Ошибка HTTPS: проверь сеть/VPN. API обходит зависание SMTP-портов, но тоже требует доступа к Google; работоспособность сети не гарантируется.
- OAuth-сессия истекла: вернись в панель и начни вход заново.

Источники: [Desktop OAuth + PKCE](https://developers.google.com/identity/protocols/oauth2/native-app), [срок токена в Testing](https://developers.google.com/identity/protocols/oauth2), [Gmail scopes](https://developers.google.com/workspace/gmail/api/auth/scopes), [messages.send](https://developers.google.com/workspace/gmail/api/reference/rest/v1/users.messages/send).
